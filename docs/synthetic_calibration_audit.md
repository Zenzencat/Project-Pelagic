# Technical Audit: Synthetic Calibration Ambiguity in Project Pelagic

**Date**: 2026-09-06  
**Topic**: Investigation into synthetic SAR data generation ($\sigma^0$-like values) vs. calibration squaring (`calibrate_to_sigma`)  
**Status**: Resolved & Documented (Task 8 from Roadmap)

---

## 1. Executive Summary

In Project Pelagic's data pipeline, synthetic SAR scenes generated by `src/data/generate_synthetic.py` simulate ocean backscatter directly in **linear power** ($\sigma^0$), centered around $0.063$ ($-12\text{ dB}$) for VV and $0.010$ ($-20\text{ dB}$) for VH.

However, `src/data/preprocess.py::calibrate_to_sigma()` implements standard SAR Level-1 amplitude-to-power calibration by squaring the input array:
$$\sigma^0 = \text{DN}^2 \cdot K$$

When uncalibrated synthetic data passes through `calibrate_to_sigma()`, the linear power values are squared a second time ($(\sigma^0)^2$). This doubles the negative decibel scale:
$$10 \log_{10}((\sigma^0)^2) = 2 \times 10 \log_{10}(\sigma^0)$$
transforming $-12\text{ dB}$ into $-24\text{ dB}$, and $-20\text{ dB}$ into $-40\text{ dB}$. Consequently, synthetic scenes were artificially suppressed and clipped at the lower boundary of `normalize_image()` (`min_db = -25.0 dB`).

---

## 2. Root Cause Analysis

### A. Generator Formulation (`src/data/generate_synthetic.py`)
Lines 26–40 simulate ocean backscatter in linear power:
```python
vv_mean = 0.063  # 10^(-12 / 10) = 0.0631 (linear power sigma0)
vh_mean = 0.010  # 10^(-20 / 10) = 0.0100 (linear power sigma0)
speckle_vv = np.random.gamma(shape=4, scale=1.0/4, size=(size, size))
vv = np.full((size, size), vv_mean, dtype=np.float32) * speckle_vv
```
The generator treats these values as true backscatter cross-sections ($\sigma^0$), directly applying physical damping factors:
```python
damping_factor = 10.0 ** (-damping_db / 10.0)
vv[mask == 255] *= damping_factor
```

### B. Preprocessing Calibration (`src/data/preprocess.py`)
Lines 14–23 define calibration assuming input is raw digital amplitude numbers ($\text{DN}$):
```python
def calibrate_to_sigma(image_dn, calibration_constant=1.0):
    return (image_dn.astype(np.float32) ** 2) * calibration_constant
```
For raw radar sensors (e.g., ESA Sentinel-1 Level-1 GRD), detected pixels are proportional to the electric field amplitude ($E \propto \text{DN}$), so radiometric calibration requires squaring $\text{DN}^2 / A_\sigma^2$ to obtain power.

### C. The Conflict
Because `generate_synthetic.py` outputs values in $[0.0, 0.2]$ (strictly non-negative), `preprocess_for_prediction()` branches into the non-negative branch:
```python
if np.any(image_raw < 0):
    # Real Sentinel-1 holdout imagery (already in dB)
    ...
else:
    # Linear scale
    sig = image_raw.astype(np.float32) if already_calibrated else calibrate_to_sigma(image_raw)
```
When `already_calibrated` is `False` (the default for synthetic dataloaders), `calibrate_to_sigma` computes:
$$\text{Output} = (\sigma^0)^2$$
For background ocean ($0.063$), $(0.063)^2 = 0.003969$.  
In decibels:
$$10 \log_{10}(0.003969) = -24.01\text{ dB}$$
For VH ($0.010$), $(0.010)^2 = 0.000100 \implies -40.0\text{ dB}$.

When fed into `normalize_image(image_db, min_db=-25.0, max_db=0.0)`:
- VV ($ -24\text{ dB}$) is mapped to $( -24 - (-25) ) / 25 = 0.04$ (barely above zero).
- VH ($-40\text{ dB}$) is completely clipped to $0.0$.
- Slick regions (with 5–10 dB additional damping) are fully crushed against $-25\text{ dB}$.

## 3. Scope of Impact

| Data Source | Format | Calibration Path | Affected by Squaring? | Notes |
|---|---|---|---|---|
| **Real Holdout (Zenodo)** | dB float ($\approx -30\text{ dB}$ to $0\text{ dB}$) | `np.any(image_raw < 0)` branch | **No** | Uses `10 ** (x / 10)` to convert to linear for filtering, then returns to dB. |
| **Real Live (CDSE Process API)** | Linear float ($\sigma^0$) | `already_calibrated=True` | **No** | CDSE returns calibrated `SIGMA0_ELLIPSOID` linear power; passes `already_calibrated=True`. |
| **Synthetic Dataset** | Linear float ($\sigma^0$) | `already_calibrated=False` | **Yes** | Double-squared; values compressed to near-zero. |

---

## 4. Resolution & Recommendations

1. **Synthetic Generation Correction (`generate_synthetic.py`)**:
   If `generate_synthetic.py` is intended to simulate uncalibrated Level-1 amplitude GeoTIFFs, it should emit amplitude $\text{DN} = \sqrt{\sigma^0}$:
   ```python
   # Simulate Level-1 amplitude DN
   vv_dn = np.sqrt(vv_mean * speckle_vv)
   vh_dn = np.sqrt(vh_mean * speckle_vh)
   ```
   Alternatively, if simulating calibrated products, save the GeoTIFF with an explicit metadata tag or pass `already_calibrated=True` in `src/data/dataset.py`.

2. **PR #3 Consistency**:
   PR #3 routed `run_full_preprocessing()` through `preprocess_for_prediction()`, which ensures consistent handling. Bypassing `calibrate_to_sigma` for calibrated data via `already_calibrated=True` is verified by test suite `tests/test_preprocess.py`.
